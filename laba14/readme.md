## Відповіді на контрольні питання (Лабораторна робота №14)

1. **В чому головна перевага делегування подій порівняно з додаванням обробників addEventListener на кожен окремий елемент списку?**
   * **Відповідь:** Делегування подій дозволяє повісити лише один слухач події на загального батьківського контейнера замість сотень слухачів на кожен елемент окремо. Це економить пам'ять браузера і дозволяє коректно реагувати на кліки по динамічно доданих елементах, яких ще не було в DOM під час завантаження сторінки.

2. **Як об’єкт події (event) та його властивість event.target допомагають реалізувати делегування?**
   * **Відповідь:** `event.target` вказує на конкретний дочірній елемент, по якому фактично відбувся клік. Завдяки цьому ми можемо перевірити через `classList.contains()` чи маємо справу з потрібним елементом (наприклад, кнопкою покупки).

3. **Що станеться, якщо спробувати знайти кнопку через document.querySelector і повісити на неї подію ДО того, як ця кнопка з’явиться на сторінці (наприклад, під час очікування відповіді від сервера)?**
   * **Відповідь:** Метод `querySelector` поверне `null`, оскільки елемента ще немає в дереві DOM. Спроба викликати метод `addEventListener` на `null` призведе до фатальної помилки виконання скрипта (`TypeError: Cannot read properties of null`).

4. **Навіщо у події dragover ми обов’язково маємо викликати event.preventDefault()? Що буде без нього?**
   * **Відповідь:** За замовчуванням браузери не дозволяють скидати (drop) елементи в інші блоки. Виклик `event.preventDefault()` скасовує цю заборону і дає браузеру зрозуміти, що цей блок є цільовою зоною для скидання. Без цього подія `drop` просто ніколи не спрацює.

5. **Яку роль відіграє об’єкт event.dataTransfer у подіях перетягування?**
   * **Відповідь:** Він слугує тимчасовим сховищем («буфером обміну»), який дозволяє безпечно передавати дані (наприклад, ID елемента через `setData` та `getData`) від джерела перетягування (`dragstart`) до цільової зони (`drop`).
