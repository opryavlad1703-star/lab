## Відповіді на контрольні питання (Лабораторна робота №13)

1. **В чому різниця між протоколом передачі даних (HTTP) та форматом збереження даних (JSON)? Як вони взаємодіють під час виконання методу fetch()?**
   * **Відповідь:** HTTP — це протокол прикладного рівня для передачі даних у мережі (правила запитів і відповідей між клієнтом і сервером). JSON — це текстовий формат серіалізації структурованих даних. Під час `fetch()` протокол HTTP доставляє відповідь від сервера, а метод `response.json()` розпаковує отриманий потік байтів у форматі JSON у звичайний масив або об'єкт JavaScript.

2. **Що станеться, якщо URL в функції fetch('http://nepravelniy-url.com') буде зламаний? Хто спіймає помилку і де ми це побачимо у нашому скрипті?**
   * **Відповідь:** Проміс, який повертає `fetch`, перейде у стан `rejected` через мережеву помилку (Network Error). Цю помилку перехопить блок `catch(error)` в асинхронній функції, після чого управління передасться в блок `try...catch`, а повідомлення виведеться на екран або в консоль через `error.message`.

3. **Чому ми застосовуємо метод await response.json() замість звичайного response.text() чи простого використання змінної response без методів? Що фізично зберігається у "сирому" response?**
   * **Відповідь:** У "сирому" `response` фізично зберігається об'єкт відповіді мережі (`Response`), який містить службові заголовки, статус, статус-текст та потік даних (`ReadableStream`). Метод `response.json()` асинхронно зчитує цей потік і парсить його в об'єкт/масив JS. `response.text()` повертає сирий рядок замість готової структури.

4. **Які основні методи (verbs) HTTP-запитів ви знаєте, крім GET? Чому за замовчуванням fetch() робить саме GET?**
   * **Відповідь:** Основні методи: `POST`, `PUT`, `DELETE`, `PATCH`. Метод `GET` за замовчуванням виконується тому, що його єдине призначення — безпечне отримання (читання) даних із сервера без зміни його стану.

5. **Для чого більшість публічних API (як-от FakeStoreAPI, Weather API) використовують ключі доступу (API Keys) і чому ми у нашому тестовому API обійшлися без нього?**
   * **Відповідь:** Ключі доступу потрібні для ідентифікації користувачів, захисту серверів від DDoS-атак, лімітування кількості запитів (rate limiting) та збору статистики. У нашому тестовому навчальному API ключі відсутні, оскільки воно створене виключно для ознайомлювальних та навчальних цілей у відкритому доступу.
