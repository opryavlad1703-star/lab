## Відповіді на контрольні питання (Лабораторна робота №16)

1. **У чому полягає фундаментальна відмінність між localStorage та sessionStorage за тривалістю життя та областю видимості даних?**
   * **Відповідь:** `localStorage` зберігає дані постійно (персистентно) без обмеження в часі — вони залишаються доступними навіть після закриття вкладки, браузера чи перезавантаження пристрою. `sessionStorage` є сесійним сховищем — його дані існують виключно протягом життєвого циклу поточної вкладки браузера і автоматично видаляються при її закритті.

2. **Чому при збереженні об'єктів або масивів у localStorage необхідно використовувати метод JSON.stringify(), і що станеться, якщо спробувати зберегти об'єкт напряму?**
   * **Відповідь:** Web Storage приймає виключно рядкові дані (`DOMString`). Якщо спробувати зберегти об'єкт напряму, браузер автоматично викличе для нього метод `.toString()`, через що у сховищі збережеться рядок `"[object Object]"`, і ви втратите всі вихідні дані. Метод `JSON.stringify()` перетворює складну структуру на валідний JSON-рядок.

3. **Які обмеження за обсягом пам'яті діють для Web Storage API, і як обробляти ситуацію переповнення квоти сховища (QuotaExceededError)?**
   * **Відповідь:** Зазвичай ліміт обсягу пам'яті для Web Storage становить близько 5–10 МБ на один домен. У разі спроби записати дані понад ліміт браузер викидає виняток `QuotaExceededError`. Для його обробки запис у сховище загортають у блок `try...catch`, де обробляють помилку (наприклад, очищають застарілі дані або сповіщають користувача).

4. **З якої причини конфіденційні персональні дані покупця (наприклад, номер банківської картки чи пароль) категорично заборонено зберігати у відкритому вигляді у localStorage?**
   * **Відповідь:** Дані в `localStorage` не шифруються і є повністю доступними для читання будь-яким JavaScript-кодом, що виконується на сторінці. Це робить сховище вразливим до атак типу XSS (Cross-Site Scripting), через які сторонні шкідливі скрипти чи розширення можуть легко викрасти конфіденційну інформацію.

5. **За яких умов генерується подія window.storage, і чому вона не спрацьовує всередині тієї самої вкладки, яка щойно викликала метод setItem()?**
   * **Відповідь:** Подія `storage` виникає тоді, коли запис у сховищі `localStorage` змінюється з *іншої* вкладки або вікна того ж самого сайту. Вона навмисно не спрацьовує у вкладці-ініціаторі змін, оскільки ця вкладка й так знає про оновлення стану й керує ним напряму, тоді як інші вкладки потребують синхронізації інтерфейсу.
